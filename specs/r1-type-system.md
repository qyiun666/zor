# R1 最小类型系统 规范

状态：0.1.x 实施基线（原 draft-0.1；0.1.0 tag 前置项 V-2 已随实施转正，正/负例与 golden 门禁在 main）｜负责人：核心工程师
需求来源：PRD §8 R1（AC-R1-1/2/3 唯一编号来源）；OQ-2 工程口径=评审通过项（终审语义 M3 落定）。
本文件为规范性文档（normative）。措辞"必须/不得/可以"分别对应 MUST/MUST NOT/MAY。

## 1. 类型宇宙总则

类型的形成规则（WFT, well-formed types）：

```
T ::= prim | [T; N] | (T1, ..., Tk), k ≥ 0 | struct | enum | &T | &mut T | fn(...) -> T
```

除此形式外的类型表达式在 0.1.x 不存在（无泛型、无 trait bound、无 `*const T` 用户语法，FFI 指针仅 `Handle<T>`，见 R4）。

## 2. 原始类型 prim

`i8 i16 i32 i64 u8 u16 u32 u64 f32 f64 bool byte unit`

- `byte` 为独立 8-bit 无符号类型，**不**等同于 `u8` 的别名（可互转但须显式转换函数，见 §5）。
- `unit` 是唯一零大小类型，字面量 `()`。
- 无 `char`/字符串原语：字符串字面量类型为 `[byte; N]`（UTF-8 字节序列，0.1.x 不含独立字符串类型，见开放项 OI-1）。

## 3. 组合与引用类型

- **固定长度数组** `[T; N]`：N 为编译期字面量整型；N=0 合法；元素类型必须 WFT。
- **元组** `(T1,...,Tk)`：k=0 等价 `unit`；不可变长。
- **struct**：具名字段记录；字段类型必须 WFT；0 字段 struct 合法。字段分隔符规范形态为 `,`；`;` 为 0.1.x 兼容容忍形态（解析器接受逻辑 `eat(Semi) || eat(Comma)`；两分隔符均缺且未到 `}`/EOF 时报 E1101，提示文案 `expected ';' or ',' after field, found <token>`），分隔符终审归 0.2.x 语法冻结（CO-8 溯源注记）。无继承、无方法体（函数以 `fn` 独立定义并以首参接收 `&T/&mut T/T`，语法糖 0.2.x 再议）。
- **enum**：标签联合。变体形态仅两种——无字段变体 `A` 或元组变体 `A(T1,...,Tk)`。**无参变体构造形态（0.1.x 实行口径，与 AC-R1-2 正例 r1-09-enum-nullary 对齐）**：无参变体的声明形态裸 `A` 与 `A()` 均合法（parser 载荷括号为可选，源码字面 `if self.eat(&Tok::LParen)`，两种写法解析后载荷同为空）；构造拼写仅限调用形态 `Variant()`（零实参），裸变体名不是值表达式——路径表达式只解析局部绑定，裸用变体名报 E1101，文案逐字 `unknown identifier '<变体名>'`（裸名构造拼写糖留 0.2.x OI 项）。构造表达式类型为所属 enum 的具名类型；实参个数与空载荷不符报 E1601，文案模板 `变体 '<名>' 载荷 <n>，实参 <m>`（归一转写非逐字）。名字解析顺序函数优先：用户已定义同名函数时该调用点按函数签名检查（变体让位，与 check 层"先按函数查"顺序一致）；函数与变体均未命中报 E1101，文案逐字 `unknown function or variant '<名>'`。**递归禁止**：变体载荷类型不得经不经 `Box` 间址的具名类型链（直接或间接）引用该 enum 自身（如 `List = Cons(List) | Nil` 与两 enum 具名互引形态，0.1.x 不可表达并报 E1401，与钉定负例 r1-n05/n06 及 §8 码表短名行的判据一致）。经 `Box<T>` 间址的堆递归形态不在本禁令句辖界，其归口在册于 R2：`Box<T>` 为语言级内建具名句柄（R2 §5），「树/链式结构经 `Box` 递归堆」列 R2 §7 可表达清单首行，struct 字段形态钉定正例为 r2-06-box-recursive-list；enum 变体载荷的 `Box` 组合面（Box 间址自环与两 enum 具名互递形态）的覆盖状态见 R2 §7 覆盖勘定注记（0.1.9 P2 件c），本句不对其作「已开放」或「禁止」表述。原句尾「堆递归需 Box 亦未开放，列入不可表达清单 R2 §7」系归口错位——R2 §7 不可表达 7 条目中无该条目，且与 R2 §5、§7 首行、r2-06 的在册实态矛盾，随 0.1.9 P2 勘定件b 修正移除：不新增承诺、不放宽既有禁令。
- **引用类型** `&T` / `&mut T`：只能作为函数参数/局部绑定出现；不得存入 struct/enum 变体/数组元素（防逃逸，与 R2 词法作用域检查闭合）。形式规则与生命周期见 r2-ownership.md。

## 4. 字面量与推断

- 整型字面量默认 `i64`；浮点字面量默认 `f64`；`true/false : bool`；字节串字面量 `"[T;N]"` 型。
- 推断自上下文单向收敛：绑定/参数/返回任一处显式标注即固定；**禁止隐式数值转换**——`let x: i32 = 1;` 合法（字面量适配），`let y: i32 = some_i64;` 编译失败（E1201 类型不匹配）。跨类型运算须显式转换函数（`i64.to_i32()` 类内置，0.1.1 实现清单）。
- 算术/比较运算仅在操作数类型相同时合法；结果类型=操作数类型。

## 5. 赋值/移动/复制语义表（AC-R1-1，无留白）

| 类型 | `let b = a;` / `a` 作实参 | 复制方式 |
|---|---|---|
| prim（含 byte/unit） | 复制（bit-copy），a 仍可用 | 隐式 |
| `[T;N]`、元组、struct | 全部成员属 Copy 集 → 复制；否则移动 | Copy 集=成员全为 prim/`()`/递归 Copy 的数组/元组/struct |
| enum | 全部变体载荷属 Copy 集 → 复制；否则移动 | 同上 |
| `Box` 式句柄（R2 §5） | 移动 | 仅显式深拷贝函数（0.1.x 内置类型逐个定义） |
| `&T` / `&mut T` | 复制句柄本身（引用可 Copy），**不**复制指涉对象；`&mut` 复制后原句柄失效（unique-move 语义，归 R2 判定表） | 见 R2 |
| `Handle<T>`（R4） | 移动 | 禁止算术与复制 |

移动后原绑定再使用=编译错误 E2101（R2）。Copy 判定不设用户可标注接口（无 trait），由上述结构规则决定。

本节相关批次表述的消歧（0.1.x 测试面口径，语言语义面零新增）："批次增量口径"是**用例覆盖推进口径**（测试面记账规则，非语言语义），仅指 AC 批次正例逐批覆盖上表各行的执行安排。在册出处（决策日志 D-029 +《M1 判据模板·用例清单》PR#9 实测回写②）原文："本批 Copy 覆盖=0.1.1 可表达 3 行（prim/数组·元组·struct 同规则行），Box/Handle/`&mut` 复制行按类型归属留 R2/R4 批；"6 行逐覆盖"按批次增量口径执行"。该口径不蕴含任何运行期或编译期"批次"语义，不得引申为"聚合赋值的复制/移动批次语义"类未登记承诺；上表各行判定语义唯一由表列内容与本节结构规则（含无 trait 标注条款）决定，批次增量只约束覆盖节奏，不改变判定规则本身。

## 6. 函数

- 显式签名：`fn name(p1: T1, ..., pn: Tn) -> R`；无 `R` 时视为 `-> unit`。
- 单返回值；多值用元组。重载不存在；名字作用域=模块级唯一。
- 递归允许（调用图无静态限制；栈溢出为运行期错误，0.1.x 不做深度检查）。
- 一级函数：可作参数/返回值的仅 `fn` 名（函数指针语义，同签名可比）；闭包表达式 0.1.x 不提供（与 R3 spawn 捕获规则联动，见开放项 OI-2）。
- 内置 I/O 调用 `println`/`print`（0.1.x 实施归口，判定在 check 层，与 check.rs 特判逐字对源）：
  - 生效条件：仅当用户**未定义**同名函数时，此二名按内建特判调用（特判条件源码字面 `(n.as_str() == "println" || n.as_str() == "print") && !self.fns.contains_key(n)`）；用户自定义同名 `println`/`print` 时特判让位，按普通函数签名检查（含实参个数不符 E1601，文案模板 `调用 '<name>' 实参个数 <got>，签名要求 <want>`）。
  - 实参与返回：各实参逐个做类型检查（无期望类型约束）；不提供格式串/参数格式化承诺（0.1.x 无任何格式化语义）。调用表达式类型为 `unit`。
  - 诊断：`println` 零实参报 E1601，文案逐字 `println 至少一个参数`（即"至少一参"语义入册）；`print` 零实参合法。

## 7. 溢出与边界行为（Edge cases，PRD v1.1 勘误归本节）

- 整型算术溢出：**debug 构建 checked**（每次算术生成运行期检查，溢出=运行时终止错误 E30xx 类，带源行号），**release 构建 wrap**（模 2^N 回绕）。工程实现按 OQ-1 方案 B 用 C 内建 `__builtin_*_overflow`，零额外运行时依赖。
- 除零：debug/release 一致，运行期终止错误。
- `f32/f64` 不适用溢出语义；IEEE754 行为直通（NaN 不视为错误）。
- 终审口径 M3 落定（D-012）；本节措辞已按 debug checked / release wrap 成文，若终审变更须同步升 draft-0.2 并触发 T-5 用例修订。

## 8. 编译期诊断要求（负例判据载体，AC-R1-2）

每个类型错误必须输出：`错误码(E1xxx) + 源文件:行:列 + 错误类型名 + 一句事实描述`。最小码表：

E1101 未知类型名｜E1201 类型不匹配｜E1202 隐式转换禁止｜E1301 数组长度非编译期常量｜E1401 enum 递归变体｜E1501 引用类型不合规出现位置｜E1601 函数签名/实参不一致。

E1101 覆盖面消歧（0.1.x 实施基线；本条款为释义说明，不新增/不注销任何错误码）：E1101 为跨 lexer/parser/check 三层共享的标识符/解析失败码——码表短名"未知类型名"仅为速记不实，其实发覆盖面至少含三层形态：lexer 层标识符未解析、parser 层期望 token 未命中（含 §3 struct 字段分隔符行 `expected ';' or ',' after field, found <token>`）、check 层名字求解未命中；逐层实发点全量编目留 0.2.x 语法冻结窗口，不入本版（消歧不注销）。check 层调用点口径入册：函数与变体均未命中的调用报 E1101，文案模板 `unknown function or variant '<名>'`（与 §3 名字解析顺序句的在册承诺句同串），与 check.rs 实发点源字面 `format!("unknown function or variant '{}'", n)` 字节级对合——该源字面的渲染形态即 `unknown function or variant '<名>'`，双向逐字对源。

E1501 释义扩写（0.1.x 实施基线；本表为释义说明，不新增/不注销任何错误码。码表短名"引用类型不合规出现位置"为速记，实发覆盖面含引用、参数化与指针三类语法禁则。下表与 compiler/src 的 E1501 实发点集合一一对应（共 10 处：parser.rs 7 + check.rs 3），提示文案逐字如实转写）：

| # | 实发层 | 触发形态 | 提示文案（逐字） |
|---|---|---|---|
| 1 | parser·条目层 | `fn` 名后接泛型/生命周期尖括号 | `0.1.x 禁泛型/生命周期尖括号语法（无静态参数）` |
| 2 | parser·条目层 | `struct` 名后接泛型尖括号 | `0.1.x 禁泛型尖括号` |
| 3 | parser·条目层 | `enum` 名后接泛型尖括号 | `0.1.x 禁泛型尖括号` |
| 4 | parser·类型标注层（容器位） | `&`/`&mut` 出现在 struct 字段、enum 变体载荷、数组元素或 `Box<...>` 内 | `引用类型不得出现在容器位置（0.1.x 禁逃逸）` |
| 5 | parser·类型标注层 | 裸指针类型 `*T`/`*const T`/`*mut T` | `裸指针类型非法（FFI 仅 Handle<T>，0.1.x）` |
| 6 | parser·类型标注层 | 生命周期标注 `'a` | `生命周期标注语法在 0.1.x 不存在` |
| 7 | parser·类型标注层 | 具名类型（内建 `Box` 除外）后接尖括号 | `0.1.x 无泛型类型参数（具名类型禁尖括号）` |
| 8 | check·类型求解层 | 数组元素求解为引用类型 | `数组元素不得为引用类型` |
| 9 | check·类型求解层 | 引用类型经容器路径进入类型求解（in_container） | `引用类型不得出现在容器位置` |
| 10 | check·语句层 | `let` 标注为引用类型（持久化） | `引用类型只能出现在函数参数/局部借用，不得作为 let 标注持久化` |

注：#4 与 #9 文案近同但分属 parser/check 两实发点（#4 含后缀"（0.1.x 禁逃逸）"，#9 无）；`&mut x` 表达式借用与函数参数 `&T/&mut T` 位为合法形态（§3 引用类型条目），不触发本码。

可达性注记（0.1.14 P3 随实同步；本条只记实发路径的覆盖状态，不新增/不注销任何错误码，不改本表任何单元格文字与 §8 码表数值）：**#8 自 0.1.14 起对数组字面量推导形态的首元素求解可达**——0.1.13 及以前该文案仅经「显式标注数组类型」与「嵌套容器路径」两路实发，推导绑定形态（`let a = [&x, &y];`）此前静默通过（即 0.1.13 所登记的实体缺口面 A），本版为补该路径可达性，检查设施、错误码与提示文案全部沿用本行在册串，未新增检查器、未新增码位、未新写文案；**#8 的首诊覆盖范围仅到首元素求解**——非首元素持引用的数组字面量（如 `let a = [x, &y];`）不发本码，而由既有的元素一致性判定路径发 E1201 拦下（两态均非零退出、禁则不破，无静默逃逸），故本行触发描述「数组元素求解为引用类型」的逐元素字面读法与实发点覆盖面在本版仍不完全对齐（释义行文的精确性同步另窗处置，本窗不改本表文字）；**#9 维持原态**＝`in_container` 兜底位在当前语法可达面内对推导形态仍不可发。附带实发面（0.1.14 合入件实测背书，本窗不另增用例）：`[&x]`、`[[&x]]`、`[&mut x, &mut y]`、`[&x, x]` 四类形态现均落在本禁则实证域内。

错误文案为黄金文件基线（门禁 T-4），改动走 PR+QA 评审。
